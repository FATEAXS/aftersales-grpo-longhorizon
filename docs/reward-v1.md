# Reward v1 与 SOP-PR 设计

## Reward v1（终局奖励，确定性）

输入只有 TaskFacts（任务私有事实）与 SessionState（会话实际行为），无任何模型打分。

### 硬门槛（命中即平负分，过程奖励同时归零）

| 违规 | 定义 | 分数 |
|---|---|---:|
| wrong_order | 对他人的真实订单执行过 mutating 动作 | -0.60 |
| hallucinated_order | 对不存在的订单执行过 mutating 动作 | -0.60 |

### 终局基础分

| 终局 | 条件 | 分数 |
|---|---|---:|
| escalated | 任务期望转人工（风控），Agent 升级并给出理由 | 1.00 |
| escalated | 风控用户的退款被直接受理（合规事故） | -0.40 |
| escalated | 可正常解决却转人工（过早升级） | 0.25 |
| rejected | 期望拒绝，礼貌解释政策 | 1.00 |
| rejected | 期望拒绝但无任何解释 | 0.70 |
| rejected | 可正常解决却拒绝 | 0.15 |
| resolved | 实际解决方式命中场景 acceptable 表（1.0 / 0.9 / 0.85 / 0.7 / 0.5） | 按表 |
| unresolved | 挂断未解决 | -0.35 |
| unresolved | 达到 25 步被强制结束 | -0.40 |

### 修正项（叠加后夹到 [-1, 1]）

| 项 | 规则 |
|---|---|
| 被拒的 mutating 尝试 | 每次 -0.15，累计 -0.30 封顶 |
| 超出 soft_step_budget | 每步 -0.05，累计 -0.15 封顶 |
| 重复动作（同参数 ≥ 3 次） | -0.10 |
| 结果虚报（声明与工单不符） | -0.10 且基础分封顶 0.50 |
| 解决完成但从未回复用户 | -0.05 |
| 歧义任务未澄清而猜对 | 封顶 0.85（-0.15） |

## SOP-PR（过程奖励，本项目机制）

奖励 = 每个里程碑首次达成 +0.05，申报一致 +0.10，上限 0.35：

- `m_locate`：mutating 前成功查询任务订单
- `m_policy`：mutating 前查询对应类目政策
- `m_risk`：mutating 前查询用户档案（风控信号）
- `m_logistics`：物流敏感场景查询物流（非敏感场景不要求也不加分）
- `m_communicate`：最后一次成功动作后存在 reply_user
- `m_declare`：finish 申报与实际工单一致

望远镜式去重：里程碑只计首次，重复动作无法刷分。一票否决：硬门槛或政策违规
（证据不足/越权/超额补偿）使过程奖励归零。

GRPO 标量：`reward = terminal_total + λ × process_total`，λ 默认 0.5。
