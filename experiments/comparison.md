# Baseline → SFT → GRPO → 合规重加权 GRPO → λ 消融

同一 Final-100 Clean 留出任务(100)、同一 AftersaleSimulator v1.0 世界、
同一 Reward v1(终局)+ SOP-PR(过程)评分口径。基座 Qwen3-1.7B,单张 RTX 3090。

| 阶段 | 严格成功率 | 平均 Reward | 红线违规率 | 应拒绝却办理率 | 结果虚报率 |
|---|---:|---:|---:|---:|---:|
| Baseline | 28.0% | 0.054 | 57.1% | 48.0% | 21% |
| LoRA SFT | 81.0% | 0.824 | 0.0% | 56.0% | 1% |
| GRPO v1(30 步,均匀采样) | 82.0% | 0.838 | 0.0% | 56.0% | 0% |
| 合规重加权 GRPO(λ=0.5) | 77.0% | 0.798 | 0.0% | **32.0%** | 3% |
| 合规重加权 GRPO(λ=0) | **82.0%** | **0.838** | 0.0% | **32.0%** | 0% |
| 合规重加权 GRPO(λ=1) | 77.0% | 0.810 | 0.0% | **28.0%** | 3% |

合规重加权 = 场景分层采样 + 拒绝/风控场景 ×2 过采样 + 风险加权优势(×1.5) +
组内最优基线 + 多内层 epoch PPO 裁剪(±0.2) + 成本敏感补偿 +
解释一致性里程碑 + 时间线校验。

## 消融结论

1. **P0 机制有效**:v1 的 30 步 GRPO 完全没动"应拒绝却办理率"(56%);
   v2 在 λ=0(即去掉过程奖励、只靠分层/过采样/风险加权/PPO 裁剪)下把它
   降到 32%,成功率保持 82%——合规修复不再以成功率为代价。
2. **SOP-PR 的 λ 用于调节合规与成功率的权衡**:λ=0 → 82%/32%;λ=0.5 → 77%/32%;
   λ=1 → 77%/28%。λ 越大模型越保守(更多拒绝、更少违规办理),但任务成功率
   下降。业务可按偏好选点:追求解决率选 λ=0,追求最严格合规选 λ=1。
3. 红线违规率在所有训练后阶段保持 0。
4. 过程奖励减分的来源推测:解释一致性里程碑鼓励更长的政策解释回复,
   使模型把更多生成长度用于政策解释,减少了执行类动作;v3 方向是把 m_explain 的奖励权重
   与任务类型解耦。



## 负结果:朴素 SFT 数据重加权会灾难性破坏已有能力

为进一步压违规率,尝试在 SFT 阶段做上游对齐:新增 200 条拒绝/风控占 85% 的
加强任务,与原 346 条直接混合后重训(SFT v2,训练 loss 反而更低)。结果:

| 指标 | SFT v1 | SFT v2(85% 拒绝类混入) |
|---|---:|---:|
| 严格成功率 | 81.0% | **29.9%** |
| 解决类场景(换货/错发/未收货/价保) | 高 | **全部 ≈ 0%** |
| 拒绝类场景(blocked_no_reason / late_complaint) | 中高 | 88.9% / 78.6% |
| 红线违规率 | 0% | 28.6%(不降反升) |

特征符合灾难性干扰:高重复度的拒绝模板(仅 3 类场景)破坏了多样化解决能力,连风控转人工也退化为紊乱行为。下游 GRPO v3 继承该坏基线
后同样失败(57%,起步组内成功率 25% ≈ SFT v2 的 30%)。

从这次失败得到三点:

1. 合规重加权放在 RL 阶段(优势加权/采样配额)是无损的,GRPO v2 λ=0
   已验证(82% + 32%);SFT 数据混合的破坏性远大于 RL 重加权;
2. 若确需 SFT 阶段重加权,拒绝类占比应控制在 ≤20%,或采用课程式交错而非
   直接混合;
3. 更换 SFT 基线后必须先评测基线再接下游——GRPO v3 的失败在起步组内
   成功率(25% ≈ SFT v2 的 30%)处已有信号,当时未及时归因。

## 局限

- 每格单次 greedy 评测;变体间差 1pt 在 100 任务下不具统计显著性,
  差 4-5pt 视为趋势性结论;
- GRPO v2 仅 40 步、组大小 4×2,处于小规模验证量级;
- λ 曲线仅 3 个点,不足以精确定位最优点。
